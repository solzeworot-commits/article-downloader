# Передача работы: портативный «Загрузчик статей» v6.0

Документ для следующей сессии Claude. Здесь задача, что сделано, как устроено, что
проверено и что осталось.
Репозиторий: https://github.com/solzeworot-commits/article-downloader Пользователь пишет по-русски, отвечать ему тоже по-русски.

## 1. Задача (словами пользователя)

- Есть рабочий загрузчик статей v5.24 (`original_v5.24/`): скачивает PDF по DOI, ссылке
  или названию через выделенный Яндекс.Браузер (CDP, порт 9223) и институциональный
  доступ. Раньше он жил на одном рабочем компьютере: трей-вотчер, очередь `inbox\*.csv`
  + `.ready`, синхронизация через OneDrive.
- Нужно сделать **портативную** версию: папка распаковывается на любом компьютере с
  Windows и работает без установки.
- Доступ к подпискам через **«Войти через организацию»** (Shibboleth/OpenAthens), то есть
  вход на сайтах издательств через университет.
- Все компьютеры на **Windows**.
- Нужен понятный интерфейс: куда вставить или загрузить DOI и **ярко выраженная кнопка
  запуска**.
- Сценарий «как обезьяне»: *двойной щелчок по значку → открывается браузер со всеми
  базами → пройти капчу → дальше можно уходить: скачивание начинается само, без
  каких-либо действий*.
- **Яндекс.Браузер оставить основным**: в нём проверка (капча) Elsevier «держится» дольше
  всего.

### Изменения в `article_downloader.py` (полный diff в `changes_article_downloader.diff`)

- Браузер больше не только Яндекс: `ARTICLE_BROWSER` = `auto` | `yandex` | `edge` |
  `chrome` | путь к exe. В режиме `auto` порядок такой: Яндекс → Edge → Chrome
  (`dedicated_browser()`, `find_browser_exe()`).
- Профиль: `%LOCALAPPDATA%\ArticleDownloader\<YandexProfile|EdgeProfile|ChromeProfile>`.
  Профиль Яндекса тот же, что у v5.24: на рабочем компьютере сохранятся старые входы.
  Профиль намеренно лежит не в портативной папке: куки шифруются DPAPI под пользователя
  и компьютер, так что при копировании папки входы всё равно не переедут, а свои учётные
  данные пользователь не раздаст вместе с папкой. Переопределяется через
  `ARTICLE_PROFILE_DIR`.
- `ARTICLE_BROWSER_ARGS`: дополнительные ключи браузера (нужны для теста на Linux).
- Функции переименованы: `ensure_yandex_running` → `ensure_browser_running`,
  `restart_*`, `stop_dedicated_browser` (теперь через psutil, PowerShell остался запасным
  путём и запускается с `CREATE_NO_WINDOW`), `browser_profile_dir`, `BROWSER_CDP_URL`.
- Новые режимы командной строки:
  - `--warmup bases.json`: открыть вкладку на каждую базу и ждать, пока ни на одной не
    останется проверки. Печатает `WARMUP|<key>|<state>|<detail>`, где state: loading,
    captcha, ok, error, closed. Вкладку с капчей выводит на передний план. Когда всё
    чисто, закрывает свои вкладки. Код выхода 0 — всё пройдено, 10 — истекло время
    (`ARTICLE_JOB_DEADLINE`).
  - `--open URL...`: открыть вкладку в браузере загрузчика (для входа через организацию).
  - `--restart-browser`.
- Обычный вызов `article_downloader.py "<DOI>"` работает как раньше: строка
  `RESULT|STATUS|msg`, коды выхода 0/1/10/11/12.

### Как устроен `app.py`

- **При запуске**: поднимает сервер, открывает окно, создаёт значок «Скачать статьи» на
  рабочем столе (PowerShell + WScript.Shell, `-EncodedCommand`) и сразу запускает
  разогрев баз (`--warmup`). Незаконченные статьи из `logs/queue.json` продолжаются сами.
- **Автостарт**: поток очереди ждёт, пока идёт разогрев (`phase = warmup_wait`), и
  стартует сам, как только капчи пройдены. Если пользователь не пришёл, разогрев
  заканчивается по тайм-ауту (по умолчанию 20 мин) и очередь всё равно идёт. В окне есть
  кнопка «Начать, не дожидаясь».
- Если разогрев был больше часа назад (`WARM_FRESH_SEC`), при новом «Скачать» базы
  открываются заново.
- **Капча посреди скачивания**: загрузчик сам ждёт ручного прохождения (логика v5);
  `app.py` видит это по строке в выводе и показывает жёлтый баннер. Если время вышло,
  статья один раз уходит в конец очереди и автоматически запускается повторный разогрев.
- **Статьи** обрабатываются по одной. Каждая запускается отдельным процессом
  `python.exe` с `CREATE_NO_WINDOW`, вывод читается построчно. Сторожевой таймер убивает
  зависший процесс вместе с node и python-потомками, браузер не трогает. Между статьями
  пауза `pause_sec` (10 с), есть дневной лимит `daily_limit` (300 запусков в день).
- **Ввод**: из любого текста извлекаются DOI (скобки внутри DOI сохраняются), ссылки,
  строки `title:` и `cnki:`; по флажку строки без DOI превращаются в `title:`. Файлы:
  txt, csv, tsv, ris, bib, enw, nbib (utf-8 или cp1251), xlsx и docx разбираются через
  zip/xml без сторонних библиотек.
- **Файлы в папке программы**: `settings.json`, `logs/queue.json`, `logs/app.log`,
  `logs/.ui_token`, `Отчёт.csv` (UTF-8 с BOM, разделитель `;` — для Excel), `pdf/`, а
  также `inbox/`: списки оттуда подхватываются каждые 20 с и переносятся в
  `inbox/_добавлено/`.
- **Вторая копия** (повторный запуск или файл, брошенный на значок, пока программа
  работает) передаёт файлы работающей копии через `/api/hello` и показывает её окно.
- **Безопасность**: сервер слушает только 127.0.0.1, проверяет заголовок Host, все API
  требуют токен.
- Без окна больше 15 минут и без работы программа завершается сама.
- **Базы и ссылки для входа** заданы в `BASES` в `app.py`: ScienceDirect, SpringerLink,
  Nature, Wiley, ACS, T&F, Oxford, MDPI, Frontiers, CNKI, eLIBRARY. Если в очереди есть
  DOI этого издательства, для разогрева открывается сама статья (`https://doi.org/<DOI>`):
  так срабатывает настоящая проверка.

## 4. Что НЕ проверено — главное для следующей сессии

1. **Ничего не запускалось на Windows.** Проверить:
   - Python из NuGet: `pythonw -E -s`, дочерний `python.exe` с `CREATE_NO_WINDOW`,
     конвейеры stdout;
   - запуск Яндекс.Браузера и Edge с `--remote-debugging-port=9223` и профилем из
     `%LOCALAPPDATA%`;
   - окно Edge `--app` (если его нет — `webbrowser.open`);
   - создание значка на рабочем столе, `os.startfile`, остановку браузера через psutil;
   - распаковку zip с кириллическими именами в Проводнике; предупреждения SmartScreen и
     пометку «файл из интернета» (MOTW).
2. **Настоящие издательства в v6 не проверялись:**
   - распознаёт ли `WARMUP_CHECK_WORDS` (в `article_downloader.py`) реальную проверку
     ScienceDirect/Cloudflare в Яндексе;
   - работают ли ссылки входа через организацию в `BASES` (`app.py`):
     `sciencedirect.com/user/institution/login`, `wayf.springernature.com`,
     `/action/ssostart` у Wiley, ACS и T&F (Atypon) — правдоподобные, но не проверенные;
   - подпись «access provided by …» — только подсказка, распознаётся эвристикой.
3. Код скачивания — это v5.24, он работал у пользователя. В v6 менялись только запуск
   браузера и оболочка вокруг. Поиск `title:` в v6 не проверялся.

## 5. Известные ограничения и идеи

- На рабочем компьютере старый трей-вотчер v5 использует тот же порт 9223 и тот же
  профиль Яндекса. Одновременно их запускать нельзя: перед тестом закрыть трей v5.
- Из v5 не перенесены `doctor.py`, трей и удалённое управление через `remote_control\`.
  Вместо них окно программы и папка `inbox\`, которая работает, пока программа открыта.
- `queue.json` и логи лежат в папке программы. Если одна папка в OneDrive открыта на
  двух компьютерах одновременно, будут конфликты копий.
- После капчи во время разогрева вкладки закрываются; проверка Cloudflare сохраняется в
  cookie профиля. Если окажется, что Яндексу нужна открытая вкладка, это поведение
  меняется в конце `run_warmup()`.
- Дневной лимит считает попытки, а не успешные скачивания.
- Каждый новый компьютер требует одного входа через организацию: это следствие DPAPI.

## 6. План следующей сессии (на Windows)

1. `python tools\build_portable.py` (или взять готовый `ArticleDownloader_Portable.zip`)
   и распаковать в короткий путь.
2. Тестовый стенд на Windows с **отдельным профилем**, чтобы не трогать настоящий:
   ```
   python -m venv .venv
   .venv\Scripts\pip install playwright psutil pypdf
   start .venv\Scripts\python tests\fake_site.py
   set ARTICLE_PROFILE_DIR=%TEMP%\ad_test_profile
   .venv\Scripts\python tests\harness.py dist\ArticleDownloader\scripts tests\list.txt
   ```
   `harness.py` подменяет базы одним поддельным издательством. Капчу «проходит»
   `tests\pass_captcha.py` или человек в окне браузера. Состояние показывает
   `tests\state.py dist\ArticleDownloader`, снимок окна — `tests\shot.py`.
3. Реальный прогон вместе с пользователем: двойной щелчок по `СКАЧАТЬ СТАТЬИ.bat`,
   открываются ли базы в Яндексе, ловится ли капча ScienceDirect, вход через
   организацию, 5–10 DOI из его старых списков (например, `10.1021/jf4024195`).
4. Исправить найденное в `portable/`, пересобрать, отдать zip пользователю.

## 7. Чего не делать

- Не решать и не обходить капчи автоматически: только ждать, пока человек пройдёт сам
  (так было и в v5).
- Не убирать паузу между статьями и дневной лимит по умолчанию: за частые скачивания
  издательства блокируют весь диапазон IP университета.
- Не класть в архивы и репозитории личные PDF, логи и профиль браузера пользователя.
