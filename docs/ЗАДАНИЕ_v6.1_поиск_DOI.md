# Задание v6.1: стартовое окно с двумя кнопками и поиск DOI в Scopus / Web of Science

Перед началом прочитай `HANDOFF.md`: там устройство версии 6.0, которую нужно доработать.
Пользователь не программист и пишет по-русски. Все тексты в интерфейсе — по-русски.

## Идея пользователя (своими словами)

> Портабл-версия с иконкой. Кликаешь два раза — появляется окошко с двумя кнопками:
> «Получить список DOI» и «Скачать статьи».
> «Получить список DOI» открывает окошко ключевых слов, по которым идёт поиск DOI статей
> в Scopus и Web of Science; из найденного формируется список на скачивание в .txt и
> сохраняется в папку, например inbox.
> «Скачать статьи» открывает папку inbox, где выбирается файл с DOI, и начинается
> скачивание статей.

## Что сделать

### 1. Стартовое окно

После двойного щелчка по значку (или `СКАЧАТЬ СТАТЬИ.bat`) открывается окно с **двумя
большими кнопками**:

- **🔎 Получить список DOI**
- **⬇ Скачать статьи**

Это первая страница того же окна `app.py` (`portable/scripts/ui/index.html`). Нынешний
экран очереди становится вторым экраном, на него ведёт кнопка «Скачать статьи».

- **Базы при запуске больше не открываются.** Разогрев (`--warmup`) запускается только
  после того, как выбран файл для скачивания.
- Если в `logs/queue.json` остались незаконченные статьи, на стартовом экране показывается
  заметная плашка «Есть незаконченный список: N статей — [Продолжить]». Сама очередь без
  нажатия не стартует.
- Значок на рабочем столе, `.bat`, перетаскивание файла на значок (сразу в очередь) и
  передача файла уже запущенной копии остаются как в 6.0.

### 2. «Получить список DOI»

Окно поиска:

- **Ключевые слова**: поле на несколько строк, каждая строка — слово или фраза.
  Переключатель: «все слова (И)» / «любое из (ИЛИ)».
- **Где искать в статье**: название + аннотация + ключевые слова (по умолчанию) или только
  название.
- **Годы**: с … по …; **тип**: статьи / обзоры / всё; **максимум результатов** (по
  умолчанию 200, жёсткий потолок 2000).
- **Источники** (галочки): Scopus, Web of Science, OpenAlex (бесплатно, без ключа;
  по умолчанию выключен).
- Под формой показываются готовые запросы для Scopus (`TITLE-ABS-KEY(...)`) и WoS
  (`TS=(...)`), собранные из полей. Опытный пользователь может их поправить руками.
- Кнопка **«Найти»** показывает, сколько нашлось в каждом источнике и сколько уникальных
  DOI после объединения. Ниже таблица для предпросмотра: название, год, журнал, DOI,
  источник, с галочками, чтобы убрать лишнее. Дубликаты объединяются по DOI без учёта
  регистра. Записи без DOI не попадают в список, но их число показывается.
- Кнопка **«Сохранить список»** записывает `inbox\ГГГГ-ММ-ДД_<первые слова запроса>.txt`:
  по одному DOI на строку, UTF-8. Рядом, в `inbox\_подробно\<то же имя>.csv`, сохраняются
  метаданные (UTF-8 с BOM, разделитель `;`, для Excel). После сохранения в окне есть
  кнопка «Скачать эти статьи сейчас», которая сразу ставит список в очередь.

#### Как получать данные: два режима, оба обязательны

**А. Через API (автоматически, если введены ключи)**

- **Scopus Search API** (Elsevier): ключ бесплатно на dev.elsevier.com. Доступ к поиску
  даётся по IP сети университета или по `insttoken`, который выдаёт Elsevier по запросу
  библиотеки. Из дома с одним ключом API может отказать — в этом случае показать
  понятное сообщение и предложить режим Б.
- **Web of Science Starter API** (Clarivate): ключ на developer.clarivate.com.
- **OpenAlex**: без ключа. Код для работы с OpenAlex уже есть в `article_downloader.py`.
- Адреса, параметры запросов, разбиение на страницы, поля DOI и квоты **сверь с
  актуальной документацией** — по памяти не пиши. Показывай остаток квоты, если API его
  возвращает. На ошибки 401/403/429 выдавай понятные сообщения по-русски.
- **Ключи вводятся прямо в окне «Получить список DOI»** (просьба пользователя), а не
  только в настройках. Это блок «🔑 Ключи доступа» вверху окна:
  - поля «API-ключ Scopus», «Insttoken Scopus (необязательно)» и «API-ключ Web of Science»;
    после ввода значение показывается скрытым (`••••1234`), есть кнопка «Изменить»;
  - у каждого источника кнопка **«Проверить ключ»**: пробный запрос и ответ простыми
    словами: «работает» / «ключ неверный» / «нет доступа с этого компьютера — нужна сеть
    университета или insttoken» / «исчерпана квота»;
  - рядом ссылки «Где взять ключ» (dev.elsevier.com, developer.clarivate.com) и
    подсказка в одну-две строки, как его получить;
  - пока ключей нет, блок развёрнут, а галочки Scopus/WoS в режиме API не включаются,
    с пояснением: «введите ключ или используйте режим „Через браузер“»; когда ключи
    сохранены и проверены, блок сворачивается в строку «🔑 Scopus ✓  WoS ✓ [изменить]».
- Ключи хранятся в `%LOCALAPPDATA%\ArticleDownloader\keys.json`, не в портативной
  папке: папку копируют другим людям. Их нельзя писать в журналы и отдавать в окно
  целиком — только последние 4 символа. **Ключи никогда не коммитить.**
- Базовые адреса API переопределяются переменными окружения, например
  `ARTICLE_SCOPUS_URL`, `ARTICLE_WOS_URL` и `ARTICLE_OPENALEX_URL`: это нужно для тестов
  с поддельным сервером.

**Б. Через браузер (без ключей; пользователь сам нажимает «Экспорт»)**

У пользователя доступ через «Войти через организацию» в браузере, поэтому этот режим
должен работать везде.

- Программа открывает в браузере загрузчика (тот же профиль, CDP 9223, команда `--open`)
  страницы расширенного поиска Scopus и WoS. Запрос подставляется в адрес, если сайт это
  позволяет; если нет, он копируется в буфер обмена с подсказкой «вставьте и нажмите
  Поиск».
- Пользователь нажимает на сайте «Экспорт». Подсказка в окне программы: Scopus — CSV или
  RIS с полем DOI; WoS — «Plain text» или «Tab-delimited».
- Программа ловит скачанный файл: папку загрузок профиля через CDP
  `Browser.setDownloadBehavior` направить в `inbox\_экспорт\` или следить за ней. Из файла
  извлекаются DOI (`parse_entries` / `file_to_text` в `app.py` уже понимают такие файлы),
  дальше тот же предпросмотр и «Сохранить список».
- Плюс кнопка «Загрузить файл экспорта…» для файла, скачанного вручную.
- **Нельзя автоматически листать и разбирать страницы результатов Scopus/WoS** (это
  скрейпинг, он нарушает условия сервисов). Только официальные API и экспорт, который
  нажимает человек.

### 3. «Скачать статьи»

- Открывается **стандартное окно Windows «Открыть файл» сразу в папке `inbox\`**
  (например, через PowerShell `System.Windows.Forms.OpenFileDialog` с
  `InitialDirectory`, запуск с `CREATE_NO_WINDOW`).
  Фильтр: txt, csv, xlsx, docx, ris, bib.
- В окне программы рядом показывается список файлов из `inbox\`: имя, дата, сколько
  DOI, сколько из них уже скачано. Выбрать можно и щелчком по строке.
- Выбранный файл встаёт в очередь, дальше всё как в 6.0: открываются базы → капча →
  автостарт → экран очереди.
- **Автоматический подхват файлов из `inbox\` (`inbox_loop` в `app.py`) убрать.** Теперь
  `inbox\` — библиотека списков, и пользователь сам выбирает, что качать. Взятый в
  работу файл не перемещать. Отметить, что он скачан, можно в `logs/` или в имени
  отчёта.

## Что не ломать

- Логику скачивания по издательствам в `article_downloader.py`, работу с капчей
  (только ручная, без обхода), паузу между статьями и дневной лимит по умолчанию.
- Портативность: только стандартная библиотека и уже включённые пакеты (`playwright`,
  `psutil`, `pypdf`). Если без нового пакета никак, добавить его в
  `tools/build_portable.py` и объяснить зачем.
- Тексты и подсказки должны быть понятны человеку, который не программист.

## Как проверять (ты в облачном контейнере, не на Windows)

- Ни Windows, ни настоящего доступа к Scopus/WoS у тебя нет, и это нормально.
- Сделай поддельный сервер API (по образцу `tests/fake_site.py`) с ответами в формате
  настоящих API. Ответы составь по документации и сохрани как образцы.
- Сделай поддельный файл экспорта для режима Б.
- Расширь тестовый стенд и `tests/parse_test.py`: сборка запросов, объединение и
  дубликаты, записи без DOI, ошибки 401/403/429, сохранение txt и csv, выбор файла.
- Прогони всё на Linux (Chromium в Xvfb, как описано в `HANDOFF.md`), сделай снимки
  новых экранов в `screenshots/`.
- Собери программу: `python tools/build_portable.py`. Нужен доступ к api.nuget.org и PyPI.
